🚀 PLANIFICACIÓN DE CLASE

Mejoras Avanzadas · Relación entre Listas · Búsqueda automática del responsable

🎯 Competencia General

El estudiante implementa una mejora avanzada en el sistema de "Registro de Incidentes", agregando un flujo de Power Automate que, al crearse un incidente desde Power Apps, busca automáticamente al responsable en una segunda lista de SharePoint (relación entre listas) y asigna al responsable correspondiente según la categoría del incidente.

📖 Conceptuales (Saber)

  • Comprende el concepto de relación entre listas.
  • Reconoce la acción "Obtener elementos" con filtro OData.
  • Identifica cómo usar condiciones para asignar responsables.
  • Entiende el uso de campos de búsqueda (lookup) en SharePoint.

🛠️ Procedimentales (Saber hacer)

  • Crear una segunda lista "Responsables" con categorías.
  • Agregar un campo de categoría a la lista "Incidentes".
  • Configurar un flujo que busque al responsable según la categoría.
  • Actualizar el incidente con el responsable encontrado.
  • Notificar al responsable automáticamente.
  • Probar el sistema completo con la búsqueda automática.

❤️ Actitudinales (Saber ser)

  • Muestra interés por la automatización avanzada.
  • Valora la importancia de las relaciones entre datos.
  • Participa activamente en la mejora del sistema.
  • Desarrolla pensamiento lógico para resolver problemas complejos.

Actividad: "¿Cómo asignamos automáticamente al responsable correcto?"

Metodología: Reflexión y contextualización.

El docente pregunta: "Actualmente, cuando se registra un incidente, el responsable se asigna manualmente. ¿Cómo podríamos asignarlo automáticamente según la categoría del incidente? Por ejemplo: si es un problema de red, que se asigne al equipo de redes."

📌 Mejora propuesta:
  • Problema actual: El responsable se asigna manualmente al crear el incidente.

  • Flujo mejorado: Al crear un incidente, el flujo busca en la lista "Responsables" quién corresponde según la categoría y lo asigna automáticamente.

🔹 Parte 1: Crear la lista "Responsables" en SharePoint

1
Crear la lista "Responsables"

Ir al sitio de SharePoint y crear una lista en blanco llamada "Responsables".

📋 SharePoint → + Nuevo → Lista → Lista en blanco → Nombre: "Responsables"
2
Agregar las columnas necesarias

Agregar las siguientes columnas:

  • Título (Texto) — Nombre del área o categoría (ej. "Redes", "Hardware", "Software").
  • Responsable (Persona o Grupo) — Persona asignada a esa categoría.
  • Email (Texto) — Correo del responsable (opcional, para facilitar el flujo).
📝 Columnas: Título | Responsable | Email
3
Cargar datos de ejemplo

Agregar al menos 3 registros de ejemplo:

  • Redes → Responsable: Carlos López
  • Hardware → Responsable: Ana García
  • Software → Responsable: Luis Ramírez
📋 Redes → Carlos López | Hardware → Ana García | Software → Luis Ramírez
Título (Categoría) Responsable Email
Redes Carlos López carlos.lopez@empresa.com
Hardware Ana García ana.garcia@empresa.com
Software Luis Ramírez luis.ramirez@empresa.com

↑ Lista "Responsables" con la relación categoría → responsable.

🔹 Parte 2: Agregar el campo "Categoría" a la lista "Incidentes"

4
Agregar columna "Categoría"

Ir a la lista "Incidentes" y agregar una columna de tipo "Elección" llamada "Categoría" con las opciones: Redes, Hardware, Software.

📝 Columna: Categoría (Elección) → Opciones: Redes | Hardware | Software
5
Actualizar el formulario en Power Apps

En Power Apps, editar el EditForm y agregar el campo "Categoría" para que los usuarios puedan seleccionarla al crear un incidente.

✏️ Power Apps → EditScreen → EditForm → Agregar campo "Categoría"

🔹 Parte 3: Crear el flujo con búsqueda automática del responsable

6
Crear flujo automatizado

Ir a make.powerautomate.com → "Crear" → "Flujo automatizado".

Nombre: "Asignación automática de responsable".

Trigger: "Cuando se crea un elemento" → SharePoint → Lista "Incidentes".

⚡ Crear → Flujo automatizado
🎯 Trigger: "Cuando se crea un elemento" → Incidentes
7
Agregar acción "Obtener elementos" de SharePoint

Agregar la acción "Obtener elementos" para buscar en la lista "Responsables".

  • Dirección del sitio: Mismo sitio.
  • Nombre de la lista: Responsables.
  • Consulta de filtro: Título eq 'Valor de Categoría'.
📂 Lista: Responsables
🔍 Consulta de filtro: Título eq 'Redes' (usando el campo dinámico Categoría)

💡 Se debe usar el campo dinámico Categoría Value del trigger para que el filtro sea dinámico.

📌 Filtro dinámico:

En lugar de escribir "Redes" directamente, usar el campo dinámico Categoría Value del trigger. La expresión quedaría:

Título eq '@{triggerBody()?['Categoría']?['Value']}'

Esto busca en la lista "Responsables" el registro cuyo Título coincida con la categoría del incidente.

8
Agregar acción "Actualizar elemento" para asignar el responsable

Agregar la acción "Actualizar elemento" de SharePoint para actualizar el incidente con el responsable encontrado.

  • Dirección del sitio: Mismo sitio.
  • Nombre de la lista: Incidentes.
  • Id.: Campo dinámico ID del trigger.
  • Título: Campo dinámico Título del trigger.
  • Responsable: Campo dinámico Responsable de la acción "Obtener elementos".
✅ Actualizar elemento:
Id: @{triggerBody()?['ID']}
Responsable: @{first(outputs('Obtener_elementos')?['body/value'])?['Responsable']}

💡 Se usa first() para tomar el primer resultado de la búsqueda.

9
Agregar acción "Enviar un correo electrónico"

Agregar la acción "Enviar un correo electrónico" (Office 365 Outlook) para notificar al responsable asignado.

  • Para: Campo dinámico Email de la acción "Obtener elementos".
  • Asunto: "Nuevo incidente asignado: " + Título.
  • Cuerpo: Detalles del incidente.
📧 Para: @{first(outputs('Obtener_elementos')?['body/value'])?['Email']}
📌 Asunto: "Nuevo incidente asignado: @{triggerBody()?['Título']}"

Hola,

Se te ha asignado un nuevo incidente:

Título: @{triggerBody()?['Título']}
Descripción: @{triggerBody()?['Descripción']}
Categoría: @{triggerBody()?['Categoría']?['Value']}
Prioridad: @{triggerBody()?['Prioridad']?['Value']}
Reportado por: @{triggerBody()?['Reportado_x0020_por']?['DisplayName']}

Por favor, revisa el incidente y actualiza su estatus.

Saludos,
Sistema de Registro de Incidentes
10
Guardar el flujo

Hacer clic en "Guardar" y probarlo creando un nuevo incidente desde Power Apps.

💾 Guardar → Probar creando un incidente

📌 Flujo de datos mejorado:
  1. Usuario registra un incidente en Power Apps con una categoría (ej. "Redes").
  2. Los datos se guardan en la lista de SharePoint "Incidentes".
  3. Power Automate detecta el nuevo elemento y busca en la lista "Responsables" quién corresponde a la categoría.
  4. El flujo actualiza el incidente con el responsable encontrado.
  5. El flujo envía un correo al responsable asignado automáticamente.

💡 Tips clave para relaciones entre listas en Power Automate:

• Segunda lista: "Responsables" con la relación categoría → responsable.

• Campo de relación: "Categoría" en la lista "Incidentes".

• Acción de búsqueda: "Obtener elementos" con filtro OData.

• Filtro dinámico: Título eq '@{triggerBody()?['Categoría']?['Value']}'.

• Expresión first(): Toma el primer resultado de la búsqueda.

• Actualizar elemento: Asigna el responsable encontrado al incidente.

• Notificación: Envía correo al responsable asignado.

• Manejo de errores: Usar condición empty() si no se encuentra responsable.
