📘 PLANIFICACIÓN DE CLASE

Ejercicios prácticos · Diagramas de flujo UML

🎯 Competencia General

El estudiante practica la representación de algoritmos mediante diagramas de flujo UML para tres problemas específicos: comparar dos números, clasificar un número (positivo/negativo/cero) y validar un número entre 0 y 100 indicando si es par o impar.

📖 Conceptuales (Saber)

  • Comprende la estructura de un diagrama de flujo UML.
  • Reconoce los elementos: inicio, fin, proceso, decisión, entrada/salida.
  • Identifica condiciones y operaciones en los diagramas.

🛠️ Procedimentales (Saber hacer)

  • Dibujar diagramas de flujo para comparar números.
  • Dibujar diagramas de flujo para clasificar números.
  • Dibujar diagramas de flujo con validación de rango y par/impar.
  • Interpretar y traducir diagramas a código Dart.

❤️ Actitudinales (Saber ser)

  • Muestra interés por resolver problemas con diagramas.
  • Valora la planificación antes de codificar.
  • Participa activamente en la creación de diagramas.
  • Desarrolla una actitud meticulosa en el diseño.

🟡 DESARROLLO 50 minutos

Actividad: "Diseño de diagramas de flujo para tres ejercicios"

Metodología: Explicación guiada + práctica individual/grupal en Draw.io.

📌 Ejercicio 1: Comparar dos números

Enunciado: Ingresar dos números, mostrar un mensaje indicando cuál es mayor.

Entrada: Dos números (num1, num2)

Salida: Mensaje con el mayor o "Son iguales"

📊 Diagrama de flujo UML:
Inicio → 📥 Leer num1, num2 → ❓ ¿num1 > num2?
❓ (Sí) → 📤 "num1 es mayor" → Fin
❓ (No) → ❓ ¿num2 > num1?
❓ (Sí) → 📤 "num2 es mayor" → Fin
❓ (No) → 📤 "Son iguales" → Fin
📌 Decisión anidada: primero comparar num1 > num2, luego num2 > num1, si no, son iguales.
💻 Código equivalente en Dart:
void main() { int num1 = 10; int num2 = 20; if (num1 > num2) { print("num1 es mayor"); } else if (num2 > num1) { print("num2 es mayor"); } else { print("Son iguales"); } }
📌 Ejercicio 2: Clasificar número (positivo, negativo, cero)

Enunciado: Ingresar un número, la terminal imprimirá si es positivo, negativo o cero.

Entrada: Un número (numero)

Salida: "Positivo", "Negativo" o "Cero"

📊 Diagrama de flujo UML:
Inicio → 📥 Leer numero → ❓ ¿numero > 0?
❓ (Sí) → 📤 "Positivo" → Fin
❓ (No) → ❓ ¿numero < 0?
❓ (Sí) → 📤 "Negativo" → Fin
❓ (No) → 📤 "Cero" → Fin
📌 Se evalúa primero si es > 0, luego si es < 0, si no, es cero.
💻 Código equivalente en Dart:
void main() { int numero = -5; if (numero > 0) { print("Positivo"); } else if (numero < 0) { print("Negativo"); } else { print("Cero"); } }
📌 Ejercicio 3: Validar número entre 0 y 100, par o impar

Enunciado: Ingresar un número positivo entre 0 y 100. Si es inválido, mostrar "Número inválido". Si es válido, indicar si es par o impar.

Entrada: Un número (numero)

Salida: "Número inválido" o "Par" / "Impar"

📊 Diagrama de flujo UML:
Inicio → 📥 Leer numero → ❓ ¿numero >= 0 y numero <= 100?
❓ (No) → 📤 "Número inválido" → Fin
❓ (Sí) → ❓ ¿numero % 2 == 0?
❓ (Sí) → 📤 "Par" → Fin
❓ (No) → 📤 "Impar" → Fin
📌 Primero se valida el rango, si es válido se evalúa par/impar usando módulo 2.
💻 Código equivalente en Dart:
void main() { int numero = 25; if (numero >= 0 && numero <= 100) { if (numero % 2 == 0) { print("Par"); } else { print("Impar"); } } else { print("Número inválido"); } }

💡 Tips clave para diagramas de flujo UML:

• Inicio/Fin: círculo o rectángulo redondeado.

• Proceso: rectángulo (asignación, operación, lectura, escritura).

• Decisión (if): rombo con pregunta, flechas "Sí" y "No".

• Condiciones compuestas: usar AND (&&) o OR (||) dentro del rombo.

• Módulo (%): se representa como operación dentro de un rectángulo de proceso.

• Validación de rango: usar una decisión con condición compuesta.

• Ciclos: se verán en futuras clases (no incluidos hoy).
